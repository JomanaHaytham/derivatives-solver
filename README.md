# DeriveIt — AI-Powered Derivatives Solver

**Live site:** https://jomanahaytham.github.io/derivatives-solver/

A ChatGPT-style web app that solves differentiation problems **and teaches them step by step**.
Every answer is computed and verified by **SymPy**; an optional LLM (Claude) rewrites the
explanation in friendly language and answers follow-up questions — but it is never trusted to
do the math on its own.

It works fully **without an API key**: a built-in rule engine writes the step-by-step solution,
and a built-in tutor answers common follow-ups (rule explanations, practice problems).

---

## 1. Architecture

```
┌──────────────────────────────┐        POST /api/chat        ┌────────────────────────────────────────────┐
│  Frontend (React + TS)       │ ───────────────────────────▶ │  Backend (FastAPI)                         │
│  • chat UI, sidebar history  │  { message, history,         │                                            │
│  • KaTeX math rendering      │    context }                 │  services/chat_service.py  (orchestrator)  │
│  • history in localStorage   │ ◀─────────────────────────── │     │                                      │
└──────────────────────────────┘  { content, kind, verified,  │     ├─▶ inputs/      text → problem text   │
                                     context, warnings }      │     ├─▶ math_engine/ intent, safe parser,  │
                                                              │     │    SymPy derivative, verification,   │
                                                              │     │    rule-based steps   (the truth)    │
                                                              │     └─▶ ai/          LLM explanation +     │
                                                              │          follow-ups, cross-checked against │
                                                              │          the engine        (the teacher)   │
                                                              └────────────────────────────────────────────┘
```

**The three layers are separate:** the UI never computes math; the math engine never calls the
AI; the AI only *explains* a result the engine has already verified.

### How one problem is processed
1. **Validate input** – length limits, input-type adapter (text today, image later).
2. **Classify intent** (`intent.py`) – new problem, follow-up question, or out of scope
   (integrals, limits…). Extracts the expression, variable, derivative order, implicit or not.
3. **Parse safely** (`parser.py`) – character whitelist, word whitelist, no builtins. Student
   input is *never* executed as code. Ambiguous/incomplete input → the app asks for clarification.
4. **Differentiate** (`differentiator.py`) – SymPy computes the derivative and picks the neatest
   equivalent form.
5. **Verify** – the simplified answer is checked (a) symbolically against SymPy's raw derivative
   and (b) against an *independent* high-precision numerical derivative at random points.
   Implicit derivatives are verified by a second, different symbolic derivation.
6. **Explain** (`steps.py`) – walks the expression tree, names the rule at each node
   (power, product, quotient, chain, trig, exp, log, radicals, logarithmic, implicit, higher-order)
   and records each step in LaTeX.
7. **AI explanation (optional)** (`ai/explainer.py`) – the model gets the verified answer and the
   engine's steps as a scaffold, writes a student-friendly explanation, and must end with
   `FINAL_ANSWER: …`. That answer is parsed and compared with the engine's. On a mismatch the model
   is asked to correct itself once; if it still disagrees, the AI text is **discarded** and the
   engine's steps are shown instead.
8. **Display** – the *Final answer* and *Verification* sections are always generated by the
   engine, so the app only says "verified" when a check actually ran.
9. **Context** – the response carries a small `context` object (the solved problem). The frontend
   sends it back with follow-ups, so "find the second derivative of it" and "why the chain rule?"
   refer to the right problem. Alternative methods proposed by the AI are checked the same way.

## 3. Installation

Requirements: **Python 3.10+** and **Node.js 18+** (20 or newer recommended).

### Backend
```bash
cd backend
python -m venv .venv
# Windows:          .venv\Scripts\activate
# macOS / Linux:    source .venv/bin/activate
pip install -r requirements-dev.txt
```

### Frontend
```bash
cd frontend
npm install
```

## 4. Environment variables

Copy `backend/.env.example` to `backend/.env`:

| Variable | Default | Purpose |
|---|---|---|
| `ANTHROPIC_API_KEY` | *(empty)* | Enables the AI tutor. Leave empty to run with the built-in engine only. |
| `ANTHROPIC_MODEL` | `claude-sonnet-5-5` | Model used for explanations. |
| `AI_ENABLED` | `true` | Set `false` to switch the AI off even if a key is present. |
| `AI_MAX_TOKENS` / `AI_TIMEOUT_SECONDS` | `2500` / `60` | Response size and time limits. |
| `MATH_TIMEOUT_SECONDS` | `12` | Max time for one symbolic computation. |
| `MAX_HISTORY_MESSAGES` | `16` | How much conversation history is sent to the model. |
| `ALLOWED_ORIGINS` | `http://localhost:5173,…` | CORS origins (only needed if the UI is hosted elsewhere). |

The API key is read **only by the backend**. The frontend calls `/api/...` on its own origin and
never sees the key. `.env` is git-ignored.

## 5. Running

**Development (two terminals, hot reload):**
```bash
# terminal 1
cd backend && uvicorn app.main:app --reload --port 8000
# terminal 2
cd frontend && npm run dev
```
Open **http://localhost:5173**. Vite proxies `/api` to the backend.

**Single process (production-style):**
```bash
cd frontend && npm run build          # creates frontend/dist
cd ../backend && uvicorn app.main:app --port 8000
```
Open **http://localhost:8000** — FastAPI serves both the API and the built UI.

## 5a. Free website on GitHub Pages (no server, no card) — recommended

The **static build** runs the same Python math engine *inside the browser* (with
[Pyodide](https://pyodide.org)), so the whole app is plain files that GitHub Pages can host for free.
Everything (Python runtime, SymPy, the engine code) is served from your own site — no third-party
CDN, no API key, nothing to pay. The AI tutor is not available in this mode; the built-in engine
writes the step-by-step solutions and answers common follow-ups.

1. Push this repo to GitHub (branch `main`).
2. In the repo: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Go to the **Actions** tab: the *deploy-pages* workflow builds and publishes the site
   (about 2 minutes). Re-run it from there if it ran before step 2.
4. Your site is live at `https://<username>.github.io/<repo>/`. Every push to `main` updates it.

The first visit downloads about 12 MB (the Python runtime + SymPy) and takes ~10 seconds;
after that the browser caches it and answers take well under a second.

Try the static build locally:
```bash
cd frontend
npm run build:static      # or: npm run dev:static
npm run preview:static
```

How it works: `scripts/prepare-engine.mjs` copies Pyodide from `node_modules`, the SymPy/mpmath
wheels from `engine-wheels/`, and the Python files from `backend/app/` into `static-public/`.
`src/engine/worker.ts` loads them in a web worker and calls `app/browser_entry.py`, which runs the
same `ChatService` as the server. A long computation is stopped after 45 s so the page never freezes.

## 5b. Deploying with a server (needed only for the AI tutor)

The repo includes a `Dockerfile` (builds the UI, serves UI + API from one container) and a
`render.yaml` blueprint.

**Render (free tier):**
1. Push this repo to GitHub.
2. On [render.com](https://render.com) → **New +** → **Blueprint** → pick the repo → **Apply**.
3. In the service's **Environment** tab, paste `ANTHROPIC_API_KEY` (optional — without it the app
   runs with the built-in engine).
4. Your app is live at `https://deriveit-xxxx.onrender.com`. Every push to `main` redeploys it.

Free Render services sleep after ~15 minutes without traffic, so the first visit after a pause
takes about a minute to wake up. The same Dockerfile works on Railway, Fly.io, Koyeb or Google
Cloud Run. GitHub Pages alone can't host this app, because the Python backend has to run on a server.

GitHub Actions (`.github/workflows/tests.yml`) runs the backend tests and the frontend build on
every push.

## 6. Testing

```bash
cd backend && pytest -q               # 91 tests
cd frontend && npm run build && npx oxlint
```

The backend tests cover:
- **Accuracy**: one or more problems for every supported topic (constant, power, sum, product,
  quotient, chain, trig, inverse trig, exponential, logarithmic, radicals/fractional powers,
  composite, logarithmic differentiation, higher-order, implicit 1st and 2nd derivatives).
- **Verification**: a deliberately wrong derivative is caught by the numerical check.
- **Safety**: code-injection attempts (`__import__`, `lambda`, `exec`, `;`…) and malformed
  input are rejected before reaching SymPy.
- **Intent**: the example inputs from the spec, follow-up questions, out-of-scope requests.
- **AI cross-checking** with a scripted fake model: a correct explanation is accepted; a wrong one
  is corrected once; a still-wrong one is discarded in favour of the engine; wrong "another method"
  answers in follow-ups are flagged.

Manual checks worth doing in the browser: the six example cards on the start screen, follow-up
chips under a solution, "Find the second derivative of it", an incomplete input like `x^2 +`, an
out-of-scope request like `integrate x^2`, mobile width (sidebar becomes a drawer) and dark mode.

### Input syntax students can use
`x^2` or `x**2`, implicit multiplication (`2x`, `x^2 sin(x)`), `sin x`, `sinx`, `sin^2(x)`, `e^x`,
`exp(x)`, `ln(x)`, `log(x, 2)`, `sqrt(x)`, `cbrt(x)`, `|x|`, `pi`, unicode `π √ ² ³ −`.
Phrasings: `d/dx (...)`, `Differentiate ...`, `Find the derivative of ...`, `f(x) = ...`,
`y = ...`, `second derivative of ...`, `d^2/dx^2 ...`, `f''(x) for f(x) = ...`,
`... with respect to t`, `find dy/dx if x^2 + y^2 = 25`.

## 8. Known limitations & next steps
- **Image input** is not implemented yet. Add an `ImageInputAdapter` in `backend/app/inputs/base.py`
  (OCR or a vision model that returns the math as text) and an upload button in `Composer.tsx`;
  nothing else needs to change.
- The AI's *final* answer is machine-checked, but wording and intermediate lines in an AI
  explanation are not individually verified. The engine's steps are given to the model as a
  scaffold to keep them consistent, and the UI labels AI-written text.
- Partial derivatives, integrals, limits and series are intentionally out of scope.
- SymPy writes results in its own preferred form (e.g. $\tan^2 x + 1$ instead of $\sec^2 x$);
  an expanded equivalent is shown when it is shorter or more familiar.
- Conversation history lives in the browser (localStorage). For accounts across devices, add a
  database-backed conversation store behind the same API.
- Very large expressions skip full symbolic simplification and rely on the numerical check; the
  verification note says so.
